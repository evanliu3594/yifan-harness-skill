# Data Visualization：数据可视化

## Overview

图是研究结论的载体，也是最容易“口径悄悄错”的环节。本技能守六条纪律。**EDA 先行**：每张图都有数据依据与明确意图。**每图一脚本**：图可由脚本独立重跑。**图面诚实**：截断、剔除、Σ≠、负值必须在 figure caption 注明。**图面清爽**：避免不必要的次级标签与描述，让图片本身来解释说明；实在解释不了的放进 figure caption。**图内数字由数据计算**：结果性数字一律引用变量，禁止写死。**双 QA 收口**：结构 QA 复算数值，视觉 QA 目检。

**REQUIRED SUB-SKILL**：`scientific-agent-skills/sas-analysis-methodology/scientific-visualization` 与 `nature-skills/nature-figure`，二者给出判图标准与出版级样式基线。本技能在两者之上加研究管线特有的约束。两者对图面注记的建议与 Iron Law 6 冲突时，按 Iron Law 6 执行。

## Iron Law

1. **无 EDA 依据不出图。** 每张图必须能指回 insight/ 的分析结论或编号建议（Vn/Gn）。“这张图画出来好看”不是理由。
2. **改图必改脚本重跑。** 禁止手工编辑图片文件。改配色、标注或数据时，一律改 figN 脚本重新生成。
3. **图面诚实。** 数据每经过一次视图处理，都必须在 figure caption 声明。视图处理包括剔除离群、截断、只保留正单元、Σ≠加总口径、剔除后份额变化。图内只留在读图点上必需的标记，如轴标签与单位、截断箭头、比例尺。
4. **图件不占用计算 step。** figN 只读消费 output/ 与 data/proc/。图件脚本不改口径，不算新结果。口径一律沿用 output 表。
5. **图内数字一律由数据计算，禁止写死。** 标题、副标题、`annotate()`、`geom_text()`、`geom_label()`、图例名里，不得出现硬编码的**结果性数字**——凡是会随代次、口径、样本变化的值，都必须写成 `sprintf("…%.2f…", 变量)` 或 `paste0()` 引用脚本里已算出的变量。**允许写死**的只有结构常量：年份、维度数（如 17 大区、9 物种、8 品类）、TopN、阈值定义、配色与字号。
   - 判据：问一句「换代之后这个数会变吗」。会变 → 必须算；不会变 → 可以写死。
   - 为什么单列一条：`stopifnot` 断言只保护**进入计算的值**，保护不了**印在图上的字**。本机实测事故（2026）：图注标题里写死「最大跨境流 11,686 人」，换代后数据已是 11,935，而脚本的断言早已同步到新值、照常通过，于是错误数字被图件一路带进交付包，跨两代才被发现。断言通过 ≠ 图面文字正确。
   - 附带要求：`sprintf()` 跨行时，续行缩进按所在调用的 2 空格递进（不是悬挂对齐），否则 `indentation_linter` 会报错并逼你改风格。
6. **图面清爽，说明进 caption。** 图上只保留读图必需的标记：面板号、轴标签与单位、图例条目、比例尺、显著性符号。次级标签、括号解释、方法细节、口径声明写进 figure caption。图底不加「注：…」行。判据有两条。删掉这段文字图仍能读懂 → 删掉，移入 caption。删掉就读不懂 → 留在图上最靠近对应元素处。

## When to Use

以下四类工作适用本技能。

- 规划整套图件（主图 + SI）方案。
- 实现单张图（figN / SI_Fig_S*）。
- 结果更新后整代重渲。
- 图件审计前的自查，或审计发现问题的修复。

## 流程（五步）

流程分五步，编号即顺序。

### ① EDA 先行（insight/）

- 预注册探索问题，Q1–Qn 写在脚本头部。EDA 只读消费 output/。数值全部可复算，并注明源表与 sheet。
- 产出：数据字典与维度、缺失结构、分布与离群（及剔除敏感性）、核心量之间的关系。**数据质量发现单列成节**，不静默修改。
- 可视化建议编号化，分三类。**Vn** 是方案，含面板设计、数据源、命名。**Gn** 是缺口，指现有图没覆盖的关键信息。**An** 是升级项，指已有图待改进。

### ② 图件方案

定整套图的骨架：每张图一张卡片。卡片写明意图（回答什么问题）、面板划分与数据源（output 哪张表哪个 sheet）。卡片再写命名（figN_名称）与对应的 Vn/Gn。主图讲主线故事。SI 承载细节与方法学（覆盖、敏感性、加和性、对齐）。

### ③ 脚本落地（走 code-implementation）

每图一脚本 `figN_名称.R`，可独立运行。公共主题、色板、导出函数收进 `_fig_common.R`（theme、save_pub_fig、中文标签映射等）。

### ④ 双 QA

双 QA 缺一不可：结构 QA 复算数值，视觉 QA 逐面板目检。

| QA | 做法 | 不通过的典型 |
|---|---|---|
| **结构 QA** | 数值复算：图上关键统计量与 output 表/insight 报告逐值一致；行和=上游合计 | 色阶范围用了含离群的列、堆叠没归一、份额分母错 |
| **视觉 QA** | 逐面板目检：文字渲染（中文无豆腐块）、图例、碰撞、对齐、色盲可辨、注记密度 | 标签重叠、图例遮挡、字体缺字形、图底注与括号说明 |

**NOT AUDITABLE 如实标注**：某项 QA 因环境限制做不了时，标“NOT AUDITABLE，待人工”。不得假装已检。环境限制包括无图像输入、审计工具缺依赖。

EDA 报告结构、图件卡片、诚实注记清单与整代重跑清单见 [references/eda-vizgap-template.md](references/eda-vizgap-template.md)。

### ⑤ 代次管理

口径变化时，**全部图整代重跑**，不要新旧代混用。新代加 `<yyMMdd>` 后缀，落在 pics/。旧代图件直接删除，figN 脚本归档到根 `deprecated/pics/`，删除在 handoff 记一行。`pics/README.md` 的图件清单要更新代次与 QA 记录。

## 出版级样式基线（默认约定，项目可覆盖）

- 主题：theme_classic 系、小基字号（6.5pt 级）、细轴线、白底。中文字体按环境选可用字形（如 Microsoft YaHei）。**先测字形，再全量渲染**。
- 尺寸：按目标版式设计，双栏 183mm 或单栏 150mm。多面板对齐。
- 图面文字：只留定位与读值所需的文字。目标为 Nature 系期刊时，图件不带图底注与括号说明；方法细节、口径声明与统计定义全部进 figure caption。
- 导出：PNG 300dpi 起步。投稿需要时恢复 PDF/TIFF 600dpi，用 `formats` 参数化，不删能力。
- 色板：配色克制。语义稳定（负担=砖红、经济=深蓝类固定语义）。品类、区域各一套，全局一致，色盲可辨。
- 地图：投影约定固定，如罗宾逊 `+proj=robin`，**必须显式 `default_crs=4326`**。排除南极。注意官方边界口径：中国国界修复类问题按项目登记处理。
- 矩阵热图：方形矩阵用 `coord_equal()`/aspect.ratio=1。log 色阶要标注底数与单位。
- 色阶 `limits` 用**上图数据列**的范围，不用全矩阵极值。离群单元会压扁有效色阶。此时用受控变换 √/log 或分步色阶，并注明。

## Red Flags — 停下

下列信号出现时，回到对应步骤重做。

- 图脚本能跑，却说不清“这张图回答什么问题” → 回①。
- 在图脚本里重新计算或改口径，没有直接用 output 表 → 违反 Iron Law 4，回③改数据流。
- 图上数值与 output 表对不上，哪怕“只差一点” → 结构 QA 未过，排查口径。
- 视觉 QA 没做就说图完成 → 未完成。做不了就标 NOT AUDITABLE。
- 用一列的 max 定色阶，图上画的却是另一列 → 实战踩坑：矩阵极值 53.1 vs 数据列 21.6。limits 必须取上图列。
- 标题、副标题或注记里出现**手写的结果性数字** → 违反 Iron Law 5，回③改成 `sprintf()` 引用变量。跑一遍「图内数字审查」：把脚本里所有出现在引号内、且不属于格式串的数字逐个问「换代会变吗」。
- 图上出现括号解释或图底「注：…」行 → 违反 Iron Law 6，删掉并移入 figure caption。

## 常见合理化（都是借口）

下表中的借口都站不住，遇到就按右列处理。

| 借口 | 现实 |
|---|---|
| “先出图看看，EDA 以后补” | 没有依据的图会混进论文并被审计打回；EDA 先行不可绕 |
| “手工把那张图的白边裁一下就好” | 改图必改脚本；手工编辑的图与脚本产物从此分叉 |
| “注记太挤了，省掉剔除说明” | 诚实注记不可省；挤就缩面板，不删注记 |
| “新旧几张图差个代次无所谓” | 代次混用=口径混用；整代重跑 |
| “自动审计工具装不上，就当过了” | NOT AUDITABLE 如实标注 + 人工补检；假装已检是伪造 QA |
| “这个数字是定论，不会变” | 换代、换口径、换样本都会变。判据是「换代后这个数会变吗」，不是「我现在觉得它不会变」 |
| “写死了但断言也写了，双保险” | 断言护的是计算值，护不了图面文字。实测事故：断言已同步到 11,935，标题仍印 11,686，跨两代才被发现 |
| “图底加一行「注：…」，读者不用翻 caption” | 期刊排版会丢掉图底注。说明进 caption，图面留白 |
| “括号里补一句口径，显得严谨” | 括号挤占图面。口径声明进 caption，图内只留必需标记 |

## Verification Checklist

逐项勾选，未勾选项即未完成。

- [ ] 每张图有编号依据（Vn/Gn/An 或用户明确指定）与一句话意图
- [ ] 数据源全部现行（非旧代），口径与 output 表一致
- [ ] 所有视图处理（剔除/截断/正单元/归一化与否）已在 figure caption 声明
- [ ] 图面清爽：图内只留读图必需的标记，无括号解释与图底「注：…」行
- [ ] 结构 QA：关键统计量与源表逐值一致（留记录）
- [ ] 图内**结果性**数字全部由脚本计算（`sprintf()` 引用变量），无硬编码；仅年份、维度数、TopN、阈值等结构常量可写死
- [ ] 视觉 QA：逐面板目检通过，或如实标注 NOT AUDITABLE 待人工
- [ ] 脚本可独立重跑；产物代次统一；旧代结果已删除、图脚本已归档
- [ ] `pics/README.md` 图件清单与 QA 记录已更新；handoff 已留痕
