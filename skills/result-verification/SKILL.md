# Result Verification：验证结果

## Overview

验证先于完成：代码跑完 ≠ 结果正确。本技能定义三层验证。第一层是**脚本内 QC 门**，自动执行，每次运行。第二层是**事后审计报告**，由人工或 AI 系统性核对，只增不改。第三层是**宣称完成前的收口检查**。

证据标准沿用 `hdd` 的等级制。等级从高到低：V1 现场复现，V2 证据链闭合，V3 部分闭合，V4 类比，V5 纯推理（**不构成证据**）。

## Iron Law

以下四条是硬约束，验证前逐条对照。

1. **验证不通过不放行。** 阻断级问题（Blocker）清零之前，下游阶段不得使用该结果。下游阶段指可视化引用、手稿采信、对外汇报。
2. **每个 QC 值可复算。** 报告里的判定数字必须能被独立重跑得到。写不出复算路径的结论，降级为“未验证”。
3. **审计报告只增不改。** diagnosis/ 下报告一经定稿，不再改写。复审另立新文件，或在文末追加“补记”；新报告生效后旧报告删除，handoff 记一行。
4. **区分实现错误与固有缺口。** 验证发现的问题先分类。实现或口径错误要修，回 code-implementation 或 research-design。数据或方法固有缺口登记进缺口表，在论文中交代，不“修”。

## When to Use

以下情况使用本技能。

- 一个 step 脚本跑通后、进入下一步之前（QC 门 + 事后核对）。
- 数值存疑、上下游对不上、审稿人质疑某个数。
- 阶段性全量审计：代码↔设计、图件↔设计、手稿↔管线。
- 任何“做完了”的宣称之前（收口检查）。

- `nature-skills/nature-statistics`：审计稿件里已有的统计报告，包括实验单元、重复与图注统计。

## 第一层：脚本内 QC 门（自动）

QC 门每次运行都执行。设计 QC 时按性质分两类，**不得混淆**：

| 类别 | 语义 | 实现 | 失败处置 |
|---|---|---|---|
| **相等校验** | 数学上必须成立（守恒、加和、恒等） | `stopifnot(abs(diff) < tol)`，tol 量级按物理量纲定（1e-9 至 1e-6） | 脚本中止，查根因（完整 HDD） |
| **统计输出** | 已知不相等、只量化差异（独立子情景 Σ≠All、对齐损失） | 计算并打印/落 qc sheet，**不**设阈值、**不**归一化掩饰 | 数值异常时登记诊断，不改数 |

QC 编号全局登记（QC0、QC1…），每条写明：关系、阈值、实测值。配套手段：

- **锚点校验**：选历史跑、文献或手算已知的具体单元值，如“China|Pork 源国中国 66,263”。逐位或按容差比对，专抓“整体分布对但个别单元错位”。
- **交叉核对**：同一量经两条等价路径计算，如 food 路径与绝对场 delta 路径。差值应 < 1e-6 级，专抓口径漂移。
- **不变量**：Baseline 恒 0、空情景恒 0、恒等式输入输出（total = food + nonfood）。
- **分布异常扫描**（HT 前置的 anomaly detection）：查三类异常。一是本不该有的全 0 或全同值列。二是离群单元，如微型领土 49.5 µg/m<sup>3</sup>。三是计数与预期不符。整体模式的异常一眼可见，先看模式，再看单点。

## 第二层：事后审计报告（diagnosis/）

本节定审计类型、审计矩阵与报告分级。

审计类型按成本递增，按需选用：

| 类型 | 做法 | 证据等级 |
|---|---|---|
| 静态通读 | 对照设计文档逐行读代码，不运行 | V3 至 V4（需运行证据补强） |
| 运行时核对 | 读产物实测维度/锚点/QC sheet | V2 |
| 重跑验证 | 独立重跑脚本比对结果 | V1 |
| 微型 V1 复算 | 抽样单元用独立实现（另写临时脚本）复算逐位比对 | V1（局部） |
| 独立对照 | 两个互不知情的方法/子代理分别核对再汇总分歧 | 视方法而定，分歧项必查 |

审计矩阵（阶段性全量审计的四个方向）：

| 审计 | 对照物 | 抓什么 |
|---|---|---|
| 代码 ↔ 设计 | `R/_CALCULATION-ARCHITECTURE.md` 公式链 ↔ stepN 代码 | 实现与口径脱节、契约违反 |
| 图件 ↔ 设计 | figN 脚本 ↔ 图件意图 + 数据契约 | 口径错、旧代数据源、缺诚实注记（应在 caption）、图面多余注记 |
| 手稿 ↔ 管线 | 手稿公式/数值 ↔ 设计规范文件 + output 表 | 公式冲突、数字对不上、手稿自相矛盾、术语与 CSV 术语表不一致 |
| 产物 ↔ 产物 | 上游 sheet ↔ 下游汇总 | 传递损耗、重复加权、口径混用 |

报告模板与分级（Blocker / Must-fix / Info）见 [references/audit-report-template.md](references/audit-report-template.md)。

## 第三层：收口检查（宣称“完成”之前）

宣称“完成”之前，对每一项交付物做收口检查。逐条回答：

1. 它的验收标准（AT/QC/审计结论）是什么？**引原文与数值**。
2. 这些标准是何时锁定的（DEV 之前？）——事后补的标准要标注。
3. 有哪次实际运行证据（V1/V2）？没有 → 现在补，不许用“应该没问题”顶替。
4. 遗留问题清单（哪怕都是 Info 级）——零遗留也要写“零”。

答不出第 1 条，说明没有完成标准，回 code-implementation 补 AT。答不出第 3 条，说明没验证过，不许说完成。

## 发现问题后的分类处置

问题先分类，再按类别定去向。分类见下面的流向图。

```
问题发现（QC 未过 / 审计阻断 / 数值存疑）
  ├─ 实现错误（代码 bug）──────────▶ 回 code-implementation：完整 HDD 修复
  ├─ 口径错误/歧义 ────────────────▶ 回 research-design：重新拍板 + 三处同步（设计/代码/手稿）
  ├─ 数据/方法固有 ────────────────▶ 登记"固有缺口"表（量化）+ 论文 Limitations；不修数
  └─ 验证本身写错（QC 逻辑有 bug）─▶ 修 QC（完整 HDD），重跑全部相关 QC
```

修复后必须重跑受影响的全部 QC/锚点/审计结论，并在 handoff 留痕。被作废的旧审计结论，要在新报告中显式声明取代关系。

## 常见合理化（都是借口）

以下说法都是借口，不能当作省流程的理由。

| 借口 | 现实 |
|---|---|
| “整体趋势对，个别数差一点应该没事” | 审稿人揪的就是个别数；锚点校验为此而存在 |
| “这个差异 4.5% 是数据固有的，不用管” | 固有 ≠ 不用管：量化、登记、论文交代，三步都不能省 |
| “审计报告改个结论就行，不用另立文件” | 只增不改；改写的报告不可信 |
| “我重跑了，和上次一样，所以对” | 和上次一样只证明可复现，不证明正确；正确性靠 QC/锚点/交叉核对 |
| “子代理审过了” | 独立对照的价值在**分歧项**；两个都错（读了同样的错误前提）时它不保险，锚点仍是底线 |

## Verification Checklist

放行前逐条勾选。

- [ ] 新增/修改的每个计算有：≥1 条相等校验（stopifnot）或显式声明为何只能统计输出
- [ ] 锚点至少 1 个且注明来源；交叉核对（双路径）覆盖核心量
- [ ] QC 编号、关系、阈值、实测值在 `R/_QUALITY-CONTROL.md`（或项目 QC 规范文件）登记
- [ ] 审计发现的问题全部分类（实现/口径/固有/验证自身）并有处置去向
- [ ] Blocker 清零；Must-fix 有排期；Info 有记录
- [ ] 审计报告落 diagnosis/、只增不改、含修复落点（文件：行号）
- [ ] 作废结论已声明取代关系；handoff 已留痕
- [ ] “完成”宣称逐条带运行证据（V1/V2）
