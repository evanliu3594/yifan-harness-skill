# 项目原型与目录契约分型（project-conventions 深化材料）

按需加载。目录契约不按项目类型一套通吃。底座约定跨项目类型**不变**：文档分层（AGENTS 路标 + README 信息表 + 规范文件）、注入预算、handoff 交接留痕、只归档 recipe、过时结果直接删除、先听后问、写作语言。变的只有工作目录、产物形态与文件流。初始化第一步判型，判完按本文对应原型节取目录契约。

## 为什么分型

分型不讲风格，只讲代价。把数据分析契约（A 型）套在其他项目型上，代价见下表。

| 套错场景 | 后果 |
|---|---|
| 软件包项目强行建 `data/raw`、`output/`、`insight/` | 目录常年空壳，AGENTS.md 描述理想而非现实（brownfield 同款大忌） |
| 纯手稿项目强行建 `R/`、`data/proc/` | 无 step 可登记，目录级 AGENTS.md 全是占位符 |
| 仿真研究没有观测数据却硬造一个 `data/raw/` | “原始数据只读”铁律失去对象；真正要保护的 seed 与场景参数反而不在契约内 |
| 仪表盘项目沿用“日期最新一份”规则 | 部署消费的是锁定版本，“最新”恰是事故源 |

判型错误不是风格问题。它让根 `AGENTS.md` 的目录结构表、各目录 `AGENTS.md` 路标与 `README.md` 信息表、闸门检查清单都建在错误前提上。返工是整套目录。

## 判型（初始化第一步）

判型只看**交付物**，不看工具。

| 问：项目最终交付什么 | 是 → 原型 |
|---|---|
| 实证结果表 + 图 + 手稿（分析既有观测数据） | A 数据分析（默认） |
| 模拟证据：Monte Carlo、估计量性质、方法比较、功效/样本量、敏感性场景 | B 仿真/方法研究 |
| 可安装、可复用的软件包（他人项目会 install / pip install 它） | C 软件包/工具库 |
| 文字与文献综合：综述、观点、无新数据的方法学论文、基金标书 | D 手稿/综述写作 |
| 持续运行的交互应用：Shiny、仪表盘、静态站、API | E 应用/仪表盘 |

- 判定不了，或存在多个候选 → 需求确认协议。目标先开放问并回放；口径点一次列清，给出选项、影响与推荐。
- **混合型**：主原型定根目录骨架，副原型以子目录挂靠（见各原型节末“混合注记”）。
- 判型结果写入根 `AGENTS.md` 的「目录结构」与首份 handoff（“项目初始化（原型判定为 X）”）。

## 跨原型不变层

以下各条对所有原型生效，任何原型不得裁剪：

1. 文档分层（`AGENTS.md` 路标 + 专门规范文件 + 各目录 `README.md` 信息表 + `handoff/` 时间线）照旧。根模板按文末“按原型微调”替换各节内容，节结构不动。
2. 铁律五条（总纲不开工 / 改动留痕 / 归档 recipe 与删除旧结果 / 注入预算 / 先听后问）照旧。
3. **脚本（或正文源文件）是唯一事实源**。凡可由代码或源文件重新生成的产物，禁止手改，如结果表、图、`man/`、docx/pdf 导出、投稿包。改源重跑。
4. 日期后缀与“最新一份”规则适用于一切**有代次演化的产物**目录。E 型部署产物除外，见 §E。
5. `diagnosis/`（或其等价目录）只增不改。一次性验证脚本是**临时件**，用完即删；需要留痕、可复跑的才归档到根 `deprecated/diagnosis/`。
6. 五阶段技能按各原型“阶段映射”取用。不适用的阶段在根 `AGENTS.md` 的「基本规则」里声明跳过及理由。

## A 数据分析项目（默认契约）

适用：以既有观测数据回答研究问题，产物为结果表 + 图 + 手稿。目录契约见 SKILL.md 目录契约表。细则见 [directory-contract.md](directory-contract.md)，本文不重复。五阶段工作流原生匹配，阶段映射即默认。

混合注记：A 为主、含小规模模拟佐证时，`R/` 内增设 `sim_*` 脚本子族，模拟输出入 `data/proc/sim/`，不必整体改型。

## B 仿真/方法研究项目

适用：数据由程序生成（Monte Carlo、估计量性质、方法比较、功效/样本量、敏感性场景）。**没有观测 raw 数据**。“数据契约” = DGP 规格与场景矩阵。

| 目录 | 职责 | 写入规则 |
|---|---|---|
| `config/` | 场景参数：seed、样本量格、重复次数、参数组合 | **只读**（A 型 data/raw 的对应物）；一次拍板后冻结 |
| `R/` | DGP、估计量、评估指标函数 + 场景运行器 + 汇总脚本 | 函数族 `sim_*`；运行器 `run_<场景>`；汇总 `stepN_*` |
| `results/` | 模拟原始输出与汇总表 | 只由运行器写；原始 draws 日期后缀；旧代结果删除，运行器脚本归档 |
| `pics/` | 收敛诊断图 + 结果图 | figN 脚本写 |
| `diagnosis/` | 覆盖率/收敛/预算核验、复现性审计 | 只增不改 |
| `scripts/` | 方法论文手稿 | 唯一维护源 |

单向流：`config → R → results → pics/scripts`。

原型特有规则：

- **seed 制度**：seed 写进 `config/`，随场景冻结。运行器不得现场随手设。复现 = 同 config 同结果，复现审计入 `diagnosis/`。
- **重复次数、收敛判据、误差容忍度是拍板口径**（根 `AGENTS.md` 的「已拍板口径」登记）。先拍板，再放全量。
- **pilot 先行**：全量前先拿 1 至 2 个场景小规模试跑，核时耗与内存。预算写进根 `AGENTS.md` 的「主要假设与当前约束」。
- 锚点体系照用：解析解、退化情形（n→∞ 回归已知值）、与已发表数值对表。
- 超大原始 draws 可定为“只留汇总 + 运行器可复现”。该决定属口径，登记 `results/README.md` 与根 `AGENTS.md`。

阶段映射：research-design = DGP 规格/估计量/评估指标设计。result-verification = 收敛与复现核验。data-visualization、manuscript-writing 照常。

混合注记：方法 + 实证案例双线时，`results/` 之外并挂 A 型 `data/`、`output/`，实证线全按 A 型契约。

## C 软件包/工具库项目

适用：产出为可安装复用的包（R 包 / Python 包）。“手稿” = README 与 vignettes/docs；“验证” = 测试套件。

R 包（Python 对应见括号）：

| 目录/文件 | 职责 | 写入规则 |
|---|---|---|
| `DESCRIPTION`（`pyproject.toml`） | 元数据、依赖、版本号 | 版本号变更 = 拍板口径；依赖最小化 |
| `NEWS.md`（`CHANGELOG.md`） | 面向用户的发布日志 | 与 handoff 分工：NEWS 写“这版改了什么”，handoff 写“改动过程与验证” |
| `R/`（`src/<pkg>/`） | 函数源码 | 一函数一文件；导出函数带完整文档（roxygen/docstring） |
| `tests/testthat/`（`tests/`） | 单测 = 验证层 | HDD 的 AT 即单测：先写测试再实现，全绿才收口 |
| `vignettes/`（`docs/`） | 使用文档 | 与导出 API 同步更新 |
| `man/` | 帮助文件 | **衍生物**：由 roxygen 生成，禁手改 |
| `diagnosis/` | R CMD check / pytest / revdepcheck 报告 | 只增不改；发布前 check 零 ERROR/WARNING 才放行 |

关键差异 vs A 型：

- 测试套件取代 G3 审计主体。result-verification = test suite + 包检查。证据等级照用：跳过或未跑的测试如实标注。
- **发布是里程碑**：版本号、依赖策略、deprecation 周期均为拍板口径。
- 破坏性变更：旧函数不直接删。先给 deprecated 警告，过一个版本周期再移除（R 包 API 的兼容纪律）。

阶段映射：research-design = API 设计（函数契约、参数、返回值、命名）。code-implementation 照常。data-visualization 一般不适用，README 图除外，根总纲声明。manuscript-writing = README/vignettes/网站。

混合注记：包 + 配套分析（论文复现包）时，包契约为主。A 型的 `data/`、`output/` 作 `inst/`（或 `docs/`）下的挂靠子目录，按 A 型纪律管理。

## D 手稿/综述写作项目

适用：交付物是文字与文献综合：综述、观点、无新数据分析的方法学论文、基金标书、学位论文成稿。分析已在兄弟项目完成，或本就不存在。

| 目录 | 职责 | 写入规则 |
|---|---|---|
| `manuscript/` | 正文分章 markdown（`00_abstract.md`、`01_intro.md`…） | **唯一维护源**；docx/pdf 导出为衍生物 |
| `refs/` | `bibliography.bib` + 文献 PDF + 阅读笔记 | PDF 只读；笔记 `<第一作者><年份>_<短题>.md` |
| `figures/` | 自制/改编/外源图件 | 附 `SOURCES.md`：每图来源、许可、对应正文图号 |
| `notes/` | 大纲、投稿信、审稿回应草稿 | 进展性内容不进总纲 |
| `submission/` | 投稿包（衍生物） | 整包由 manuscript/ + figures/ 重新导出，不手工拼 |
| `diagnosis/` | 数值对账表、引用核验报告 | 只增不改 |

原型特有规则：

- **数字可溯源**：正文每个数值都在 `diagnosis/` 对账表登记来源。来源分三类。第一，本项目可复算。第二，兄弟项目，登记其 AGENTS 体系路径与代次。第三，文献，登记 DOI + 页码/表号。**引用前未核原文的数 = 审计债**（manuscript-writing 同款纪律）。
- **图件三态**：自制，附生成脚本指针；改编，注记原版出处与改动幅度；外源，许可凭证存 `refs/`。无凭证的外源图不得进投稿包。
- 上游联动：兄弟项目口径变更 → 本项目对账表受影响行全部重核，handoff 留痕。

阶段映射：manuscript-writing 为主干。literature-review / citation-management 照常调用。research-design 退化为大纲与论点结构设计。code-implementation、result-verification 退化为对账与引用核验。不适用处在根 `AGENTS.md` 的「基本规则」里声明。

混合注记：综述 + 一次简单再分析（meta 分析、pooled 估计）时，D 为主。再分析脚本与中间表挂 `analysis/` 子目录，按 A 型纪律管理。

## E 应用/仪表盘项目

适用：交付物是持续运行的交互应用（Shiny、仪表盘、静态站、API），用户是别人而不是自己。

| 目录 | 职责 | 写入规则 |
|---|---|---|
| `app/` | ui / server / modules（或 pages） | 模块化拆分；全局状态最小化；模块架构登记 `app/AGENTS.md`，文件清单登记 `app/README.md` |
| `data-raw/` | 种子数据生成脚本与外部源 | 同 A 型 data/raw 纪律 |
| `data/` | 打包种子数据 | 只读；由 `data-raw/` 生成脚本重建；数据版本 ↔ 应用版本对应关系登记总纲 |
| `tests/` | 端到端/冒烟测试（shinytest2 等） | 必含：能启动、核心交互路径、空数据/异常输入表现 |
| `deploy/` | 部署配置 | 凭据只留占位，真值不入库 |
| `diagnosis/` | 性能、兼容、回归核验报告 | 只增不改 |

原型特有规则：

- **锁定版本取代“最新一份”**：部署消费根总纲登记过的（应用版本 × 数据版本）组合。日期最新的产物不作数。重部署 = 显式升级版本，handoff 留痕。
- 种子数据变更 = 口径变更（应用展示的每个数字随之改变）。这类变更走需求确认协议。
- 锚点 = 关键展示数字的端到端核对（种子数据 → 应用显示值）。

阶段映射：research-design = 应用架构与信息设计。code-implementation 照常（模块即脚本单元）。result-verification = 测试套件 + 数字核对。data-visualization 限于应用内图表规范。manuscript-writing = README 与使用说明。

## 根总纲模板按原型微调

按原型微调只换各节内容，节结构不动。映射见下表，模板为 `templates/AGENTS_root_template.md`：

| 节 | A | B | C | D | E |
|---|---|---|---|---|---|
| 目录结构 | SKILL.md 契约表 | 本文 §B 表 | §C 表 | §D 表 | §E 表 |
| 基础原始数据 | 数据源清单 | DGP 规格与场景矩阵 | 依赖环境与支持版本 | 来源项目 + 文献池 | 外部源 + 种子数据版本 |
| 研究方案 | 计算管线 stepN | 场景矩阵与评估指标 | API/模块图与导出面 | 论点结构与章节大纲 | 应用架构与信息流 |
| 已拍板口径 | 业务口径 | 重复次数/seed/收敛判据 | 版本与 deprecation 策略 | 引用规范、目标期刊 | 数据版本锁定、展示口径 |
| 代理决策 | 数据源与方法代理项 | 求解器与容差代理项 | 依赖范围代理项 | 引用格式代理项 | 展示与部署代理项 |
| 假设与约束 | 方法假设 | 计算预算、近似 | 依赖可用性 | 覆盖范围界定 | 性能与托管约束 |

## 候选原型（按需再补）

以下三个方向暂不立型。教学/课程材料、深度学习实验（实验跟踪/checkpoint 制度）、数据工程管道（调度/血缘）。出现第二个真实案例再立型。原型纪律：没有真实项目支撑的原型不写，避免纸面契约。
