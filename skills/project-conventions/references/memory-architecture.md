# 记忆架构：规则、经验与陷阱的归置（project-conventions 深化材料）

按需加载。本文回答“这条内容该写进哪个文件”，并给出判定表、晋升管线、式样与退役。

## 1. 为什么不设 EXPERIENCE.md

三个失败模式，每个都有实证：

| 失败模式 | 机理 | 实证 |
|---|---|---|
| **坟场化** | 追加式文件无晋升纪律，越写越长；信息只在写入那一刻被想过，之后无人重读 | 实战项目的根 AGENTS.md 曾因堆叠历史进度被迫拆出 HISTORY.md——同一膨胀压力会原样作用于 EXPERIENCE.md |
| **双权威漂移** | 同一主题两处记载；规则改了经验没改（或反之），读者不知信谁 | 与 AGENTS.md/CLAUDE.md 并存是同构问题，解法也同构：**单一权威源**，另一份要么是指针要么删除 |
| **上下文经济** | AGENTS.md 每会话加载，经验库要起作用也得加载——为持续衰减的历史内容付常驻成本 | handoff/ 只需读最新一份即可定位“最近发生了什么” |

正确的分离轴不是“规则 vs 经验”，而是三种**文件职能**：

| 职能 | 文件 | 时态 | 加载方式 |
|---|---|---|---|
| 规范性-现行 | `AGENTS.md` 路标（根+目录级）、专门规范文件、各目录 `README.md` 信息表 | 现在时（“必须如何”“有哪些件”） | AGENTS 每会话必读；规范与 README 按需 |
| 时序性-记录 | handoff/（一份一文档） | 过去时（“何时做了什么”） | 按需读最新一份 |
| 证据性-审计 | diagnosis/ | 过去时（“如何核实的”） | 按需检索 |

经验（=踩坑与教训）不是第四种职能，是**原料**。经验的事件形态属于 handoff，证据形态属于 diagnosis。它蒸馏出的约束最终住进 `AGENTS.md` 或规范文件；文件清单类内容进各目录 `README.md`。

## 2. 晋升管线（经验金字塔）

本小节给出经验从事件层晋升到技能层的路径。

```
L0 事件层   handoff 交接条目（始终留痕；审计发现另立 diagnosis 报告）
              │ 会再咬人吗？（同一陷阱会被另一个脚本/另一个人/三个月后的你再踩？）
              ▼
L1 目录要点  目录 AGENTS.md 技术要点节 / 规范文件 —— 已验证的技术事实（工具行为、数据陷阱）
              │ 上升到项目级口径/禁令？
              ▼
L2 项目规则  根 AGENTS.md 的「已拍板口径」「基本规则」 / 规范文件的数据契约
              │ 跨项目通用？
              ▼
L3 技能层    晋升出项目，成为技能（如 yifan-r-code-style、hdd、本技能组自身）
```

**晋升判据（一次问一句）**：

- 会再咬人 → 至少晋升到 L1；
- 只在本项目此管线成立 → 封顶 L1/L2，不要升 L3；
- 无未来适用性（一次性配置事故、已废弃管线的教训）→ 留 L0，不晋升；
- 晋升时**压缩**：规则一句 + 反面案例一行；完整战史不搬运（留在 L0）。

## 3. 规则带疤（推荐式样）

裸规则只告诉读者“不许”。带疤规则还告诉读者“违反了长什么样、这事真发生过”。实战项目的规范文件写法即此式样：

> **禁二次人口加权**：S–R 受体侧值本身即人口加权 PM2.5，下游聚合直接对 S–R 值运算。
> 反面案例：260904 vizgap EDA 曾在其上再乘 WB 国家人口得“83.2% 自贡献”，属重复加权，已撤销。

| 层 | 式样 | 实例 |
|---|---|---|
| L2 规则 | 禁令一句 + 口径依据 + 反面案例一行（日期/症状/处置） | 上例；“share = 1 − ratio（表值=剩余率，勿直接当份额用）” |
| L1 技术事实 | 现象 + 正确用法 + 一行成因 | `terra::values()` 行主序（曾致掩膜退化 6.48M×1）；`as.matrix` 默认返回 ncell×nlyr；含分类维度 NC 必须 ncdf4 按维读；dplyr 禁“裸名+索引”引用同名外向量（曾把 17 区域全取 Global）；物种用显式字符串映射（曾致 OC←CO、SO2←NMVOC 错位） |
| L0 事件 | handoff 四要素（做了什么/为什么/验证带数值/口径影响） | 各交接文档的改动清单 |

注意 L1 条目的构成：**现象一句 + 正确做法一句 + 成因/战史一行**。超过三行的 L1 条目说明它其实是 L2 规则或该回 L0。

## 4. 条目退役

规则与要点不是永生的。触发退役的情形如下：

- 上游工具/依赖升级使陷阱消失（如包的新版本改了默认行为）→ 要点改写或移除，handoff 留痕；
- 所属管线/脚本已废弃 → 相关要点随目录清单处置：脚本移入根 `deprecated/<原目录>/`；要点行与旧文档删除，在该段 README 与 handoff 记录。**不**留在正文里失效占位；
- 口径变更协议触发时，旧规则条目**更新**而非删除（新旧对照在 handoff 的口径变化节里）。

退役检查时机：每次整代重跑/里程碑审计时，目录 AGENTS.md 的技术要点节（或规范文件）顺带过一遍。

## 5. 暂存区豁免（何时允许独立经验文件）

独立经验文件只在两种情形下允许，且两者都是**临时物**：

1. **brownfield 考古期**的 `diagnosis/onboard_inventory_<yyMMdd>.md`——未验证断言的集中暂存。终局是逐条晋升，或随报告删除（见 init-procedures.md）；
2. **跨项目个人教训**的酝酿期——放个人笔记。成熟一个晋升一个进技能层，不长期维护成库。

判据：暂存区必须有**终局**（晋升或删除）。没有终局的暂存区就是坟场。

## 6. 快速判定表（“这条内容写到哪”）

下表按内容类型给出去处。

| 内容 | 去处 |
|---|---|
| 绝对不可违反的约束/共识/口径 | 根 AGENTS.md 的「已拍板口径」「基本规则」（或规范文件的数据契约节） |
| 经用户拍板的决策 | 根 AGENTS.md 的「已拍板口径」表（含日期） |
| 某目录特有的技术事实/陷阱 | 目录 AGENTS.md 的技术要点节（≤3 行/条）或规范文件 |
| 某文件是什么、状态如何 | 目录级 `README.md` 文件清单 |
| 何时发生了什么、为何、验证结果 | handoff/（当次交接文档） |
| 审计过程与证据 | diagnosis/ 报告 |
| 踩坑教训（尚未蒸馏） | 先按事件写 handoff；随后按 §2 判定晋升 |
| 跨项目通用的方法论 | 技能（skill）层 |
