# 文档分层与注入预算

> 本文件是 AGENTS / README / 规范文件三层体系的操作规程。
> 一句话：**AGENTS.md 每会话注入、有总量上限；README 与规范文件按需加载。写之前先算预算，再定归属。**
> 与 `discussion` 无关，纯工程规程；本文件里的上限值可按项目调整，但**"先算再写"的顺序不能省**。

## 0 为什么要有这一层

宿主把 `AGENTS.md` 注入每一轮上下文，注入量有硬上限（DeepSeek Harness 实测 65,536 字节）。超了不报错，**静默截断尾部**——最后几节等于没写。README 与普通 markdown 不注入。

实测事故：某项目 11 个 `AGENTS.md` 合计 89.5 KB，超过预算 40%，加载时尾部被丢弃；作者以为"写了就等于生效"。

结论：文档架构的第一约束不是美观，是**哪些字会进上下文**。

## 1 注入预算模型

| 层 | 载体 | 每会话注入 | 上限建议 |
|---|---|---|---|
| 路标 | `AGENTS.md`（根 + 各一级目录） | **是** | 根 ≤9 KB；目录级 ≤1.5 KB；全部合计 ≤预算的 60% |
| 规范 | 专门文件（如 `R/_CALCULATION-ARCHITECTURE.md`、`R/_QUALITY-CONTROL.md`） | 否 | 单文件 ≤30 KB |
| 信息表 | 各目录 `README.md` | 否 | 单文件 ≤20 KB |
| 时间线 | `handoff/`（一份一文件） | 否 | 单段 ≤15 KB |
| 归档（recipe） | `deprecated/` | 否 | 不限（只读复跑；只收脚本与配置） |

测算法：`Σ(AGENTS.md 字节) + 用户级全局 ≤ 65536`，留 40% 余量给后续增长。改文档前后各算一次，写进交接。

## 2 三层分工：内容归属判定

| 内容 | 归到 |
|---|---|
| 目录定位、硬规则（必须 / 禁止）、指向 | `AGENTS.md` |
| 公式、契约、算法、QC 体系、口径细节、目录间关系 | 规范文件（按需） |
| 本目录文件清单（一行一文件）、子目录一句话 | `README.md`（按需） |
| 代次沿革、历代 QA、迁移记录 | `handoff/` |
| 锚点数值 | QC 登记表（唯一登记处） |
| 外部数据来源与文献 | 该数据所在目录 README 的「项目外数据」节 |
| 报告 / 交接的一句话摘要 | 索引行（见 §4） |

判定口诀：**每轮决策都要用到的进 AGENTS；查的时候才需要的进按需文件；会随时间变旧的进 handoff。**

五种最常见放错：清单里夹沿革、README 里写规范、规范里写目录清单、锚点散在多处、外部文献塞进总纲。

## 3 目录入口规则

- **一个目录一个入口**：一级目录 = `AGENTS.md`（路标）+ `README.md`（信息表）。
- 子目录的文件归子目录自己的 `README.md`，**不写进父 README**。
- **纯数据透传子目录可例外**：文件即数据、没有目录级规则时，在父 README 用一行登记，并**把例外名写进顶层规则**（否则下一轮又会在父 README 里展开）。
- 子目录建 README 的阈值：直接子文件 ≥3 且长期存在；同族文件（批量产物）用通配一行描述，不列举。
- **字典/清单文件的位置 = 它描述的产物所在层**。放错层是位置错误，不是"多了个文件"。例：`data/proc/` 的产物字典应叫 `data/proc/README.md`，不是 `data/PROC.md`。

## 4 索引规范

- 索引行 = 文件名 + 一句话（是什么）+ 可选一句结论（口径/判定类才有），**整行 ≤120 字符**。
- 数值、论证、做法、多个细节子项**不进索引**——正文里有，索引重复就是双重维护。
- 超纲信号："另含…""具体做法…""第一步…第二步…"出现在索引行里。
- **清单不夹沿革**。自检：日期令牌密度 = `2[0-9]{5}` 出现次数 / KB，>2/KB 基本可判夹带历史（纯手册类文件通常 <1/KB）。
- 索引本身是"导航件"，`downstream-sync` 的归档边界三问里明确它**必须随变更更新**，不属于冻结件。

## 5 引用规范

- 跨文件引用写**文件名 + 节名**，不写章节号。正例：`根 AGENTS.md 的「拍板口径」`；反例：`根 AGENTS.md §3.3`。
- 理由：章节号会因重排失效，且失效是静默的。实测某项目重编号后有 129 处 `§x` 引用需要处理。
- 唯一例外：同一文件内部的目录可以用 `§`。
- 动手前**量引用面**：`grep -c "AGENTS\.md.*§"`。活文档改，已归档的脚本不追改并在交接登记。

## 6 规范与产出：单向权威

- **规范层**（内部）回答"应该怎样"，住 `R/_*.md` 这类文件与根 AGENTS；**产出层**（对外、交付件）回答"这次是怎样的"，住 `paper/` 之类目录。
- 方向单向：**规范 → 产出**。产出由规范派生，不反向定义规范。
- 格式差异是刻意的：规范用纯文本（可 grep、可对照代码标识符 `mort_food`），产出可用 LaTeX `$$…\tag{}`（要渲染、要给外部读）。
- 两边各写一句权威声明。两份都自称"唯一"是最常见的双权威事故。

## 7 迁移七步（搬迁 / 拆分 / 合并任何文档结构）

1. **立规则**：先写归属判据（§2），再动手；把判据和上限写进 AGENTS 顶层，否则两轮后长回原样。
2. **算预算与引用面**：数目标文件体积、数入向引用。
3. **留回退点**：整目录快照或逐文件副本，记下路径。
4. **搬迁并留指针**：原位置留一行指针，不静默消失。
5. **引用清扫**：全项目替换；活文档改、已归档脚本不改并在交接登记。
6. **污染扫描**：见 §8。
7. **收口登记**：交接写清"什么从哪搬到哪、引用改几处、验证结果、回退点"。

## 8 批量改写的三个坑（实测踩过，会毁文件）

| 坑 | 症状 | 正解 |
|---|---|---|
| **数组展平** | 把"数组的数组"传给 PowerShell 函数，被展平成字符串；`$p[0]`/`$p[1]` 取到单个字符 → 变成逐字符替换，全文件污染 | 传**扁平** `"OLD@@@NEW"` 字符串数组，或按行索引替换 |
| **分隔符碰撞** | 分隔符出现在内容里（`\|\|\|\|` 撞上 Markdown 表格的 `\|`），新旧串被切错 | 用内容中不会出现的分隔符，并断言每元素恰含一个分隔符，命中数≠预期即中止 |
| **反引号转义** | PowerShell 双引号串里 `` `r `` `` `n `` 是控制符，写 `` "`raw/" `` 得到回车 + `aw/` | 含反引号的串一律用**单引号** |

**改完必做四检**：

1. **污染扫描**：查单字符替换模式、重复竖线、乱码。
2. **表格列数自检**：按空行分表，排除转义 `\|`，逐表比对列数。
3. **自指检查**：README 里出现"见 <自己>"即错（`见 `+`该文件自己的相对路径`）。
4. **残留检查**：旧路径、旧章节号在活文档中必须为 0。

## 9 recipe vs 过时结果 vs 临时件

| 类别 | 例子 | 处置 |
|---|---|---|
| **recipe** | 计算脚本、绘图脚本、管线配置、QC 与复算脚本 | 归档到根 `deprecated/<原目录>/`，在该目录 README 登记 |
| **过时结果** | 旧代中间数据、旧结果表、旧图件、被取代的报告与旧文档 | 直接删除，不归档；当次 handoff 记一行 |
| **临时件** | 一次性探针、`tmp_*`、备份副本、试探脚本 | **用完即删**，不进归档、不进清单 |

判据：**它造结果，还是它就是结果？** 造结果的（recipe）归档；结果本身过时即删；一次性探针属临时件。

删除过时结果前过“删后能否再生”门槛：recipe 已归档、输入仍在，才可删。recipe 补不出的结果原地标注并请用户拍板，不静默删。

先实测再动手：RDS 默认已是 gzip，二次压缩收益常低于 5%；"看起来很大"的目录里，最大的一两个文件往往正是必须留的。

## 10 防退化上限（写进 AGENTS 顶层）

- 根 `AGENTS.md` ≤9 KB；目录级 `AGENTS.md` ≤1.5 KB。
- 架构说明节 ≤0.8 KB，只放流程名与指针表。**出现公式、文件通信图或产物清单 = 退化信号。**
- 索引行 ≤120 字符。
- 每个 `README.md` 只有两类内容：子目录表 + 文件表；出现第三类（规范/沿革/论证）即退化。
- 每次改动文档结构后，在交接里记一次实测总量，与上限对比。
