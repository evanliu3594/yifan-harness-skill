## 4. 基本规则（全局）

- **环境**：<语言与版本；解释器调用方式；禁用项>。
- **目录与去留**：原始数据只读。派生数据写 `data/proc/`，结果写 `output/`，图写 `pics/`。只归档 recipe（计算脚本与管线配置），移入**根** `deprecated/<原目录>/`；过时的中间数据、结果、报告与旧文档直接删除，当次 handoff 记一行；**临时件用完即删**。
- **文档分工（强制）**：`AGENTS.md` 只写架构（定位、必守、指向），每会话注入、总量 ≤9 KB，超上限会静默截断；文件清单归各目录 `README.md`；规范细节归专门文件（如 `_CALCULATION-ARCHITECTURE.md`、`_QUALITY-CONTROL.md`）；沿革归 `handoff/`。
- **变更必同步（强制）**：任一口径、结论、规划、目标或计算变更后，全项目非归档件必须在同一轮回到同一代次与同一口径。五类触发、边界三问、十步见 skill `downstream-sync`；未同步项必须显式登记在当次 handoff。
- **HDD（强制）**：所有代码实现与改动遵从 skill `hdd`。先提可证伪假设与验证方式，再动手。改完以验证结果收口。机械改动可简化，但须声明“预期不变/预期值”并核对。
- **需求确认（强制，先听后问）**：目标不清时，先开放问并回放。口径点用选项、推荐和影响一次问清。代理决定必须说出口，并登记到第 3.4 节。
- **写作语言（全局）**：直白、朴素、准确。先结论，后证据与可核对数值。
- **经验归置（全局）**：踩坑教训不另设经验库。事件写当次 handoff。可复用约束晋升为规则，附一行反面案例。已验证技术事实写进目录 `AGENTS.md` 的技术要点节，或按需放进专门规范文件。一次性教训只留 handoff。
- **进度维护（强制）**：开工时建当次 handoff，随做随记。会话收口补全定稿。项目有 git 时，收口 handoff 必须提交入库。根总纲不堆叠历史。
