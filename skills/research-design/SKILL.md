# Research Design：计算设计

## Overview

设计先于代码。设计把研究问题翻译成三样东西：口径明确的公式链、管线 DAG、数据契约。口径经用户拍板锁定后，才进入实现。

设计的唯一标准是：不了解项目背景的人拿着设计文档，能说清每一步算什么、口径是什么、产物是什么。

设计从对话开始。先弄清研究意图，回放确认，再定口径和分级。你负责把话问清，不替用户拍板。

## Iron Law

以下五条是硬约束。任一条不满足，不得进入实现。

1. **口径未拍板不开工。** 任何实现只要涉及口径（定义、分母、边界、单位、基准年），开工前都要先完成设计对话：开放问、回放、执行选择归属。再按 project-conventions 的需求确认协议，拿到用户的明确答复。
2. **数据契约成文才能进代码。** 每条硬约束都是不可违反的口径规则，必须写进设计文档。代码只实现契约，不发明契约。
3. **公式与落地一一对应。** 每条方法公式都要指明落在哪个管线步骤、哪个脚本位置。改公式时，设计文档、代码与手稿三处同步改。
4. **固有限制必须显性登记。** 数据与方法固有缺口不是实现错误，但影响解读，单列成表。这些缺口最终都要写进论文 Limitations。
5. **仪式随级别走，试算不混入正式结果。** 快算、小改、项目三个级别各用各的仪式，判据见设计对话第 4 节。探索性试算必须标注并隔离。想转正，就重走 G1。

## When to Use

以下情况使用本技能。纯绘图改动和 bug 修复不适用，详见本节末尾。

- 新研究立项：从研究问题出发搭整个计算方案。
- 新增计算步骤（新 step）：先补设计再实现。
- 口径变更：修改任何已拍板口径前，重走确认流程并更新设计文档。
- 上游数据源更换/升级（版本、单位、空间分辨率变化）。
- 不确定该做多重时，先判设计级别。判据见 [references/design-conversation.md](references/design-conversation.md) 第 4 节。

纯绘图改动走 data-visualization。bug 修复走 code-implementation 的 HDD 简化流程。这两类工作仍须先判级，并留痕。

## 外部技能（按需）

## 设计流程：对话、六步与复现者检查

本流程分三段：设计对话、六步设计、复现者检查。快算与小改只走必要仪式，项目级全走。

### ⓪ 意图与分级

先判级，再按级别走仪式。判据见设计对话第 4 节。三个级别的做法如下。

- **快算**：不做设计访谈。你声明预期值或预期性质，执行后核对，当次 handoff 记一行。
- **小改**：在聊天内确认口径点和预期。不写完整设计文档，设计要点进当次 handoff。
- **项目**：走完整设计对话。先开放问，再把回放定稿写进根总纲第 1 节。接着填执行选择归属表。最后进入 ① 至 ⑥。

多个互相独立的研究问题，拆成子项目，逐一定义。中途变大就停下来说明。升级级别后，重走对应仪式。细则见 [references/design-conversation.md](references/design-conversation.md#L15)。

### ① 问题与目标

用一段话写清两件事：研究问题问什么；目标产出哪几个量、回答哪几个子问题。问题写不清楚，就回到文献与导师讨论，不进下一步。

### ② 顶层实验设计

定义实验逻辑：基线是什么，情景/处理是什么，贡献/效应如何定义，共多少组合。贡献定义示例见归零法：delta = baseline − scenario。写明每个量的语义（“单元格 = 生产国 i 为满足需求区 t 的品类 c 生产，造成受体国 r 的归因死亡数”）。

### ③ 口径清单与拍板

列出所有需要决策的口径点：分母、加总规则、剔除规则、单位、时间基准、空间分辨率、对齐方式。逐项处理：

- 给出选项 + 推荐 + 影响说明；
- 按 project-conventions 需求确认协议问用户；
- **拍板结果登记进根 AGENTS.md“已拍板口径”节**。登记时注明日期。拍板后不再改；要改，重新确认。

执行选择不冒充口径。数据源版本、语言与包、方法与模型、分辨率、交付格式，这些选择按设计对话第 3 节判归属。代理决定要说出口，并登记进根 `AGENTS.md` 的「代理决策」表。旧项目没有这一节，先补建。

### ④ 公式链（四栏结构）

对每个计算步骤，按四栏写：**方法描述（人话）**、**方法公式（数学记号）**、**运算管线**、**脚本落地**。运算管线栏标注哪个 step、什么约束。脚本落地栏写脚本名与关键行。公式编号全局唯一，手稿沿用同一编号体系。

同时维护**符号 ↔ 代码变量映射表**（E_food → `emis_food_kg`、ΔC(demand,f)(r) → `pm25[combo,r]`）。manuscript-writing 阶段直接消费该表。

### ⑤ 管线 DAG 与维度速查

本节把管线结构与各产物维度写成图与表，供下游脚本与审计对照。

- 画文件通信图，ASCII 即可。链路是：外部只读源 → step0 准备产物 → step1 → step2 → … → 图件/手稿。图上标注每条边的输入 sheet 与输出生成物。
- 配**维度速查表**，记录每个产物的文件、sheet 与数组维度。示例：`full_response` 46,292×171、`mort_attrib` [18×9×284×168]。该表是下游脚本 stopifnot 契约与审计的依据。
- 命名规范：计算步骤 `step0–stepN`（step0 = 前置准备/对齐，不计入计算管线）；图件 `figN` 独立、不占 step。

### ⑥ 数据契约与缺口表

本节登记两类内容：数据契约与缺口表。契约是硬约束，缺口表分待实现与固有两类。

- **数据契约**（硬约束，逐条编号）：任何改动不得违反。典型条目：
  - 独立子情景不强制加和相等（差异只做统计输出，禁止归一化/再分配）；
  - 统一分母（生产端与消费端共用同一基准）；
  - 块内行序契约（按位置取值，禁止按名字符串匹配）；
  - 已内嵌的加权不得二次施加（如“受体侧值本身已人口加权，禁再乘人口”）；
  - 负贡献不裁剪（数组级保留；发布视图裁剪须注明）；
  - Baseline 恒零类不变量。
- **缺口表**分两类。**待实现**是研究侧待办，含影响与状态。**数据/方法固有**条目先量化，再写处置方式；这部分直接遗传给论文 Limitations。

模板：[references/design-doc-template.md](references/design-doc-template.md)。

### ⑦ 复现者检查（项目级必做）

设计成文后、进入 G1 前，按设计对话第 6 节派独立 subagent 读设计。subagent 挑出“必须猜、猜错会改变结果”的点。三堆问题处理完毕，设计才算定稿。检查记录写进当次 handoff。

## 设计文档放哪

设计产物合并进项目的文档体系，不另立游离文档。落点是根 `AGENTS.md` 的方案概要，加上 `R/_CALCULATION-ARCHITECTURE.md` 的公式链、DAG、维度、契约与缺口（文件名按项目命名）。游离文档会过期，项目文档体系有人维护。

意图基线进根 `AGENTS.md` 的「研究问题与目标」；代理决定进「代理决策」表。复现者检查记录进当次 handoff。

## Red Flags — 停下重审设计

出现下列任一信号，停下重审设计。

- 公式写不出落地脚本位置，或脚本算出的量找不到对应公式 → 设计与实现脱节。
- 发现自己在代码里“顺便”决定口径（选分母、定剔除规则）→ 回③拍板。
- 契约条目只能用“一般来说/通常”表述 → 口径未定，回③。
- 缺口既不量化也不登记 → 回⑥；固有限制不许含糊带过。
- 设计文档读起来需要项目背景才能懂 → 重写，目标是外行可执行。
- 目标没有回放就开始列口径选项 → 选项会引导用户。回到 ⓪ 重做。
- 把“方向可以”当成口径批准 → 批准只覆盖展示过的内容。未成文的口径不算批准。
- 试算结果顺手并进正式结果 → 回到 ⓪ 重新分级，再走 G1。
- 项目级设计跳过复现者检查 → 检查出的每个“必须猜”都是契约漏洞。

## 常见合理化（都是借口）

下列说法都是借口，不能当作省流程的理由。

| 借口 | 现实 |
|---|---|
| “口径先按我理解的做，用户后面再调” | 返工成本远高于一次问清；这正是需求确认协议存在的理由 |
| “契约太细了，代码里自然会体现” | 契约不成文 = 下一个人（含未来的你）必然违反它 |
| “这个小缺口不用登记吧” | 未登记的固有缺口 = 论文被审稿人发现时的致命伤 |
| “公式和代码差不多对应就行” | 差不多的对应 = 手稿审计时的逐条冲突（实战：曾发现手稿分母与代码分母不一致且手稿自相矛盾） |

## Verification Checklist（放行进入 code-implementation）

按已判级别勾选。快算与小改只勾适用项，项目级全勾。标“项目级”的条目在低级别不适用。

- [ ] 研究问题与目标一段话成文
- [ ] 设计级别已声明（快算 / 小改 / 项目），仪式与级别匹配
- [ ] 项目级：研究意图已回放、用户确认并写入根总纲第 1 节
- [ ] 顶层实验设计明确（基线/情景/贡献定义/组合数/单元格语义）
- [ ] 全部口径点已拍板并登记根 AGENTS.md（含日期）
- [ ] 项目级：执行选择归属完成，代理决策已说出口并登记第 3.4 节
- [ ] 每个计算步骤有四栏公式链 + 全局公式编号
- [ ] 符号 ↔ 代码变量映射表成文
- [ ] 管线 DAG + 维度速查表成文
- [ ] 数据契约逐条编号成文
- [ ] 缺口表分“待实现/固有”两类，固有项已量化
- [ ] 项目级：复现者检查完成，三类问题处理完毕
- [ ] 探索性试算（如有）已标注、隔离，未混入正式结果
- [ ] 设计已并入项目文档体系（AGENTS 路标 + 规范文件 + README 信息表）并在 handoff 留痕

本级适用项全部勾选 → 进入 code-implementation。任一适用项未勾 → 不开工。
