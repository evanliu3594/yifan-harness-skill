# 设计对话：在写代码前把研究意图谈清楚（research-design 深化材料）

按需加载。本文回答一个问题：设计开始前，怎样和用户谈清楚三件事。第一，要做什么。第二，为什么做。第三，哪些选择由谁定。读者是执行 research-design 的 agent。方法改造自 superpowers v7.0.0 的 brainstorming 技能。该版本 2026-10-10 发布，MIT 许可。本文按学术研究的口径场景重写。

本文只写对话。对话通过后，回到 SKILL.md 的六步设计流程。对话是六步的入口，不替代六步。

## 0. 三条原则

设计对话的目标不是问全所有问题，而是让用户确认你理解了他要什么。为此守三条原则。

1. 先听懂，再给选项。研究目标和成功标准用开放问题问。口径点是离散选择，才用选项清单。
2. 说过的话要回放。用户确认过的内容才算已确认。你推断的内容必须标成猜测。
3. 决定分两类。用户拍板的进“已拍板口径”。你代理决定的必须说出口并登记，不能只留在代码里。

## 1. 开场：先问一个开放问题

首条消息决定用户愿不愿意继续谈。它只做两件事，顺序不能反。

### 1.1 先判断要不要访谈

先看用户已经给了什么。目标、边界、关键数据源都已给出时，再判断解读是否唯一。只有一种合理解读时，跳过访谈，直接做第 2 节的回放。目标不清，或者“为什么现在做”没有说过时，先访谈。

### 1.2 首条消息

第一句给跳过选项：“如果你已经想清楚，可以直接说‘跳过访谈’，我按你的口径做。我仍会先确认数据源和方法归属。”

第二句问一个开放问题。问题要落在具体场景，不要问抽象目标。下面三个句式可以直接用。

- “这个结果第一次要拿去回答哪个具体问题？组会、审稿回复，还是政策讨论？”
- “三年后别人引用这个结果时，你希望他们引用的那句话是什么？”
- “上一次你觉得‘这个数不对’，是在什么场景？”

### 1.3 提问的四条规则

1. 一次只问一句。第二个问题等第一个回答完再问。
2. 示例答案不挂在问题后面。示例会把用户引到你的框里。
3. 选项菜单只在用户卡住时给。用户明确要选项时，也可以给。
4. 用户说“你看着办”时，给出具体方案请他改，不继续追问。

### 1.4 要覆盖的范围

下面五块是谈话范围，不是问卷。用户已经说清楚的，不再问。

- 这个研究回答什么，边界外是什么。
- 为什么现在做，成功长什么样。
- 非目标与反目标：什么情况算“做成了但失败”。
- 已有基础：前人做法、自己试过的、现成数据。
- 用户最在意的细节，以及最怕弄错的地方。

谈到哪一块需要看材料，就提出去看。可以看项目里的数据与脚本，也可以看前人的做法和公开文献。说清要找什么，由用户决定是否去看。

## 2. 回放：把理解说给用户听

回放是设计对话的核心动作。理解了一块就回放一块，不要等全部问完。

### 2.1 四条要求

1. 长度 200 至 300 字，一段话，不用列表。
2. 用户明确说过的，写成“你的要求是……”。你推断的，写成“我猜……”。
3. 猜测要能被用户一句话纠正。纠正后重新回放，不辩解。
4. 每段回放末尾问：“哪里不对，或者缺什么？”

### 2.2 回放模板

> 我理解这个研究要回答的是 <问题>，服务对象是 <谁>，要在 <场景> 里用。成功的标准是 <可判定标准>。边界是 <不做什么>。我猜 <推断一>、<推断二>；如果猜错，后面的口径会跟着变。

### 2.3 回放通过后写在哪里

用户确认后，把回放定稿写进根 `AGENTS.md` 的「研究问题与目标」节。小改不必写总纲，把要点记入当次 handoff。

回放不是复述原话。它要暴露三样东西：你确认了什么、你猜了什么、你还缺什么。用户纠正一次，后面就少返工一次。

## 3. 执行选择归属：哪些做法由用户拍板

口径清单之外，另列一张执行选择表。用户不必懂技术细节，但要知道自己交出了什么。

### 3.1 表的结构

表头四列：选择项、归属、现在的取值、说出口了吗。选择项至少覆盖六类。数据类写数据源与版本。方法类写计算语言与主包、方法与模型。交付类写空间与时间分辨率、输出格式与交付形态、目标期刊或报告模板。归属只有三种：用户拍板、授权我定、项目现状。

### 3.2 三条规则

1. 用户没有明确表态的项，按“授权我定”处理。你仍须说出“我默认用 X，理由是 Y；不同意就换”。
2. 任何代理决定写进设计文档的代理决策表。没写进去的默认值等于没有确认。
3. 项目现状已经固定的项，标成“项目现状”，不冒充用户拍板。

反例：用户以为用 A 数据源，你默认用了 B，结果整体返工。选什么都要说出口。

## 4. 分级：先定仪式规模

谈清楚要做什么之后，先判工作量级别，再决定走多少流程。级别用平常话说，不用代号。

### 4.1 三个级别

| 级别 | 判据 | 仪式 | 产物与闸门 |
|---|---|---|---|
| 快算 | 单点数值、单图、单表；不新增或改动口径 | 不做设计访谈；声明预期值或预期性质，执行后核对 | 当次 handoff 一行；不写设计文档 |
| 小改 | 一个 step 内的改动、加一张敏感性图、换已拍板口径的呈现方式 | 聊天内确认口径点与预期；不写完整设计文档 | 设计要点记入当次 handoff；G1 简化 |
| 项目 | 新研究问题、新管线、新数据集、口径变更、要交付论文或报告 | 完整设计对话 + 设计文档 + 复现者检查 | 走 G1 完整门禁 |

### 4.2 四条规则

1. 先声明级别，再说做什么。用户可覆盖级别。级别被覆盖时，记入当次 handoff。
2. 中途变大就停下来说明。升级级别后，重走对应仪式。禁止按快算开工、按项目交付。
3. 多个互相独立的研究问题，拆成子项目。逐一定义并排顺序，不塞进一个口径体系。
4. 快算与小改也要留痕。载体是当次 handoff，不是设计文档。

## 5. 探索性试算：给探索留一个合法出口

研究常需要先试算一次，看方向对不对。这类试算不写设计文档、不锁口径，但必须守五条边界。

1. 开工前明说“这是探索性试算，不作正式结果”。
2. 产物放 `diagnosis/` 或临时目录，不进 `output/` 和 `pics/`。
3. 不进手稿、不进汇报、不引用为证据。
4. 试算结论只用于决定下一步问什么、设计什么。
5. 想保留成正式结果，就视为新请求。重新分级并走 G1。

登记表放当次 handoff，五列：试算、目的、产物位置、结论用途、是否转正。示例：

| 试算 | 目的 | 产物位置 | 结论用途 | 是否转正 |
|---|---|---|---|---|
| <名> | <要回答什么> | `diagnosis/<…>` | 决定 <下一步> | 否 |

探索性分析与确证性分析在同一份手稿里必须分区标注。确证性分析的口径必须先拍板。试算不套 HDD 的 AT/DEV 流程；正式实现仍按 code-implementation 的 HDD 走。

## 6. 复现者检查：让接手的人先读一遍

设计文档定稿后、G1 之前，派一个没有上下文的 subagent 读设计。它扮演接手实现的人，只回答一个问题：还有哪些地方必须猜，猜错会改变结果。

### 6.1 prompt 模板

> 你是不了解本项目的研究助理，要按这份设计文档独立实现整条管线。你无法联系设计者。
> 读 <路径：根 `AGENTS.md`、`R/_CALCULATION-ARCHITECTURE.md` 与相关规范文件>。
> 只报告你必须猜、且猜错会改变结果的点：每条给问题、为什么影响落地、按重要性排序。
> 文档明确交给执行者的、你能合理决定的、措辞层面的问题，跳过。
> 没有阻塞问题就回答“无阻塞问题”。

### 6.2 三堆处理

收到答复后，把问题分成三堆。

- **文档已答**：把答案写进文档，不改流程。
- **小问题**：执行者能合理决定且不改变产出时，由我定，并标成“代理决策”。
- **要用户答**：只有用户能答且会改变研究结果时，一次性打包，按重要性排序问。

### 6.3 只有一轮

复现者检查只做一轮。没有 subagent 工具时降级处理。按同一 prompt 自己换角度审一遍，并在 handoff 注明“未用独立复现者”。

## 7. HARD-GATE：没有拍板就不写代码

项目级工作有一条硬线：口径没有拍板、复现者检查没有回填，就不写实现代码，不建输出目录，不跑正式管线。

只有两个例外。第一，用户明确说跳过访谈。此时仍须确认执行选择归属，并按级别完成设计文档。第二，已登记的探索性试算。按第 5 节隔离，转正须重走 G1。

## 8. 出现这些想法就停下

下面六种想法都会把对话带偏。出现任何一种，回到对应小节重做。

| 想法 | 现实 |
|---|---|
| “先给选项省时间” | 选项会引导用户。研究目标先开放问，听完再给口径选项。 |
| “用户说方案可以，就算批准了” | 批准只覆盖你展示过的内容。没回放、没成文的，不算批准。 |
| “默认值不用特意说” | 没说出口的默认值，用户无法否决。它会在返工时暴露。 |
| “试算结果不错，顺手并进正式结果” | 并入就是新请求。回分级与 G1。 |
| “文档写细一点总没错” | 快算与小改写完整设计文档，会让人绕开框架。仪式随级别走。 |
| “复现者检查是形式” | 检查出的每个“必须猜”，都是口径或契约的漏洞。 |

## 9. 下一步

对话通过后，回到 SKILL.md 的六步设计。先写研究问题和目标，再定顶层实验设计，然后列口径清单逐项拍板。每一步的产物都写进项目文档体系（AGENTS 路标 + 规范文件 + README 信息表），不另立游离文档。
