# Manuscript Writing：文章写作

## Overview

手稿是管线的最终投影。核心要求三条：**结论先行、每个数字可对账、每条公式可回溯到代码**。写作纪律三条。第一，语言直白，遵循全局写作规则。第二，数值对账，手稿数字 ↔ output 表逐一可追溯。第三，三处同步，公式改动同时改手稿 + 设计文档 + 脚本。

**生态技能**：`scientific-agent-skills/sas-analysis-methodology/scientific-writing`（结构与文风）、`nature-skills/nature-polishing`（润色）、`scientific-agent-skills/sas-scientific-communication-publishing/citation-management` / `nature-skills/nature-ref-verifier`（引文）、`scientific-agent-skills/sas-scientific-communication-publishing/venue-templates`（版式）。本技能负责研究管线侧的硬约束。

**审计与投稿材料（按需）**：`scientific-agent-skills/sas-analysis-methodology/peer-review`（证据边界清楚的同行评审与结构化稿件评估）、`nature-skills/nature-statistics`（稿件统计报告审计）、`nature-skills/nature-data`（数据与代码可用性声明）。

## Iron Law

1. **每个数字可追溯。** 手稿中每个结果数值都能指到 output 表的具体 sheet/单元。对不上的数字不许出现。
2. **公式三处同步。** 改方法公式必须同时改三处：手稿、设计文档（`R/_CALCULATION-ARCHITECTURE.md` 公式链）、代码。只改一处即失同步，视为未完成。
3. **术语以 CSV 术语表为准。** 写作开工先建 `term_glossary.csv`（与手稿同目录），逐条写明全称、缩写、具体含义。凡涉及关键数据的用词——指标名、口径、单位、分组名、变量名——必须与表一致；表里没有的词先入表再落笔。同义改写、缩写前后不一、概念随段落漂移，都按口径错误处理。
4. **固有缺口全部交代。** 设计阶段“数据/方法固有缺口表”的每一项，都必须在 Limitations 有对应交代，含量化值。固有限制是论文的一部分，不是瑕疵。

## When to Use

以下五类工作适用本技能。

- 首次撰写方法/结果章节。
- 管线口径变更后的手稿同步。
- 数值对账、公式一致性检查。
- 审稿意见回复（配合 `nature-skills/nature-response`）。
- 中英文版本互译与同步维护。

## 写作语言规则（全局规则的写作落地）

- **先结论、后证据**：每节首句给答案，证据与可核对数值随后。
- 直白、朴素、准确。像对待外行一样阐述：读者不是你，不共享你的上下文。
- 量的表述带口径：说一个数就带单位、年份、口径（“2017 年，人均 GDP 十分位，WB 2015 不变价”）。
- 不写“显著提升/大幅改善”这类无锚定的形容。要么给数，要么删。

## 核心工件

### ① 符号约定表（手稿 §1）

手稿开头放符号表（E_food、ΔC(t,c)(r)…），与设计文档的**符号 ↔ 代码变量映射表**一一对应。读者据此可从任何公式定位到代码变量。

### ② 数值对账表（写作期维护，审计消费）

| 手稿位置 | 手稿数值 | 来源 | 复算 |
|---|---|---|---|
| §4.2 | 840,046 | health_burden_*: by_receptor Σ | ✅ 逐值 |
| §4.3 | Σ17/G ≈ 100.5% | qc sheet QC5 | ✅ |

对账时注意**近亲数字**：同一量的两种口径要在文中显式对账，不许混用。例如 840,046 vs 840,438，二者是不同校准层。

### ③ 术语表（CSV，写作开工即建）

位置与手稿同目录：A 型项目是 `scripts/term_glossary.csv`，D 型项目是 `manuscript/term_glossary.csv`。格式为 CSV，表头固定六列。

| 列 | 内容 |
|---|---|
| 全称 | 中文全称；需要英文时并入本列，如「人口加权 PM2.5 暴露（population-weighted PM2.5 exposure）」 |
| 缩写 | 全文唯一缩写，如 PW-PM2.5；无缩写留空 |
| 具体含义 | 定义、口径、边界、单位；写清它与相邻概念的区别 |
| 适用范围 | 出现在哪些章节、图表、汇报材料 |
| 禁用写法 | 历史用名与近义词，命中即改；只在特定口径可用时注明限制 |
| 定稿日期 | yyMMdd；每次改动更新 |

维护规则：

1. 关键术语第一次出现当天入表，不等成稿。
2. 缩写首次出现给全称，此后只用缩写；同一概念只留一个写法。
3. 术语变更等同口径变更：改表、全文替换、handoff 记一行。
4. 表是唯一权威源。手稿附录若列术语，由表生成，不手工维护第二份。
5. 文件存 UTF-8；给 Excel 直接打开时用带 BOM 的 UTF-8，避免中文乱码。

模板见 [references/term-glossary-template.csv](references/term-glossary-template.csv)。

### ④ Limitations 生成

从设计缺口表“固有”类逐条转化，写清三件事：是什么、量化多大、对结论的影响方向。敏感性分析结论也在此引用，前提是做过验证，如线性分配 vs 全量模型的一致性 QC。

数值对账表、公式一致性表与 Limitations 转化表的操作版式见 [references/consistency-table-template.md](references/consistency-table-template.md)；术语表的 CSV 版式与全文扫描步骤见该文第 3 节。

## 手稿 ↔ 管线审计（写作完成后、投稿前必做）

走 result-verification 的审计矩阵第三行（独立对照），做三件事。第一，手稿公式 ↔ 设计文档 ↔ 代码三方比对。第二，数值逐个对账。第三，手稿内部自洽检查。实战教训：审计曾发现手稿分母定义与代码不一致，**且手稿自相矛盾**（两节各说一套）。这类问题只有系统审计能抓，通读发现不了。

## 版本与多语言

- 手稿 markdown 为唯一维护源。导出（docx/PDF）是衍生物，重导出须留痕。**在用户明确要求前不导出其他格式。**
- 多语言版本（中/英）：指定一个**唯一权威版**，另一版为同步翻译。公式编号体系跨版本一致，或明确声明差异，例如“中文版公式不编号”。修订时两版同步，并留痕。

## Red Flags — 停下

下列信号出现时，回到对应规则处理。

- 写出一个数，说不出它来自哪张表 → 停，先建对账表。
- 为“读起来顺”改了公式的记号，却没同步代码 → 违反三处同步。
- Limitations 里出现设计缺口表没有的新问题 → 这是好发现。先回 result-verification 确认是固有还是新 bug，再入表。
- 引用了自己没核过的数（“之前报告里是 X”）→ 旧报告可能已作废。一律回到现行 output 表复核。
- 同一概念冒出第二个写法，或缩写与全称混排 → 停，回术语表统一，全文替换后重扫。
- 审稿人指出数字与文中他处不一致 → 这是审计债。全文重新对账，不要只补那一个数。

## 常见合理化（都是借口）

下表中的念头都会导致返工，出现时按右列回到规则。

| 借口 | 现实 |
|---|---|
| “这个数四舍五入差不多就行” | 差一点的数在手稿↔管线审计里全是 Blocker |
| “公式中文化改个写法没关系” | 记号一改，映射表断链，三方同步崩 |
| “Limitations 写多了显得论文差” | 固有缺口是诚实交代；藏着被审稿人挖出来才是致命伤 |
| “中英两版分别维护各自改” | 版本漂移；指定权威版 + 同步修订 |
| “术语换个同义词更雅” | 术语表存在的原因；换词=换口径，审计按禁用写法逐条扫 |
| “表里记着就行，正文写得顺口一点” | 正文换词即概念漂移；表是唯一权威源，正文只照抄 |

## Verification Checklist（投稿前收口）

逐项勾选，全部通过才能投稿。

- [ ] 全文数值对账表 100% 闭合（每个数可追溯、口径一致、近亲数字已显式对账）
- [ ] 公式三处同步核验通过（手稿 ↔ AGENTS 公式链 ↔ 代码；含符号表一致）
- [ ] CSV 术语表已建，每条六列齐备；全文（摘要、正文、图注、表头、汇报材料）与表一致，禁用写法零命中；缩写首次出现给全称
- [ ] Limitations 覆盖固有缺口表全部条目（逐条勾）
- [ ] 图表引用与 pics/ 现行代次一致（图号、代次、注记与 `pics/README.md` 图件清单相符）
- [ ] figure caption 承接图内未画出的说明（剔除、截断、Σ≠、口径、加权）；图内无图底注与括号解释
- [ ] 手稿↔管线审计报告落 diagnosis/（Blocker 清零）
- [ ] 多语言版本同步声明（如有）；导出格式遵守用户指令
- [ ] handoff 留痕；`scripts/README.md` 清单更新
