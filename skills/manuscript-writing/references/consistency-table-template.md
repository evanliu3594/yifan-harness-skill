# 一致性核对模板（manuscript-writing 深化材料）

按需加载。本文给出四种操作版式：数值对账表、公式一致性表、术语表（CSV）、Limitations 转化表。

## 1. 数值对账表（完整版式）

```markdown
## 数值对账（<yyMMdd>，手稿 v<n> ↔ 现行 output <代次>）

| # | 手稿位置 | 手稿原文数值 | 来源（表·sheet·单元/聚合方式） | 复算值 | 判定 |
|---|---|---|---|---|---|
| 1 | §4.1 | 840,046 人/年 | health_burden_global_*: by_receptor Σmort | 840,046 | ✅ |
| 2 | §4.2 | Σ17/G ≈ 100.5% | qc sheet QC5 | 100.52% | ✅ |
| 3 | §4.3 | 自贡献 44.3% | pm25 表聚合（浓度口径，非死亡口径） | 44.3% | ✅（图注已带口径） |
| … | | | | | |

近亲数字显式对账：
- 840,046 vs 840,438：同量的两个校准层（<说明>），文中 §4.1 已对账。
- 38.62 vs 40.44 Mt：8 品类 vs 全部食品，Σ8≠All（4.5%），文注在 §x。
```

操作要点：

1. 先列全：用正则扫手稿里的数字，生成候选清单。扫描范围含百分数、区间、图表引用值。
2. 溯源不到 output 表的数，单独一节标“外部来源”。文献值、参数假设都属于这类数，要注明引文页码。
3. 四舍五入规则统一，如全文 3 位有效数字。尾差在表中注明舍入方向。

## 2. 公式一致性表（三方核对）

```markdown
## 公式 ↔ 代码一致性（<yyMMdd>）

| 手稿式号 | 手稿表述 | 设计规范文件（节名） | 代码落点 | 变量映射 | 判定 |
|---|---|---|---|---|---|
| (7) | M_food(g)=M_base(g)·(C_b−C_z)/C_b | 「公式链」节 式(7) | step3_health_burden.R:62-64 | M_food→mort_food | ✅ |
| (15) | M_attr(t,c,i,r)=… | 「公式链」节 式(15) | step5_*.R:80 | M_attr→mort_attrib | ✅ |

同步状态：□ 手稿 □ 设计规范文件 □ 代码 —— 三方一致（<日期>复查，零冲突）
```

记号差异要显式登记，例如“手稿 zero-out = 代码字面名 Global”，避免审计时误判冲突。

## 3. 术语表（CSV，登记与全文扫描）

位置与列定义见 SKILL.md 的核心工件 ③。模板为 `term-glossary-template.csv`，表头固定六列：全称, 缩写, 具体含义, 适用范围, 禁用写法, 定稿日期。文件存 UTF-8；给 Excel 直接打开时用带 BOM 的 UTF-8。

```csv
全称,缩写,具体含义,适用范围,禁用写法,定稿日期
"净非本地健康负担（net non-local health burden）",NNLHB,"生产端归因死亡减发生端归因死亡；单位人/年","§4 结果、§7 讨论","净出口、净进口（仅食品贸易口径可用）",<yyMMdd>
"人均 GDP 十分位（WB 人均 GDP，2015 不变价，人口加权）",,"按世界银行人均 GDP 分十组并做人口加权","§5 公平性分解、图 5","收入十分位、收入分组",<yyMMdd>
```

全文扫描三步：

1. 禁用写法：在手稿、图注、表头、汇报材料里逐个检索；命中即改，或确认属于豁免口径。
2. 缩写：首次出现处给全称，其后只用缩写，不许全称与缩写混排。
3. 反向扫：正文里的指标名、口径、单位、分组名逐个查表；表里没有的先补入，再改正文。

## 4. Limitations 转化表（缺口表 → 论文段落）

```markdown
| 固有缺口（设计登记） | 量化 | Limitations 落点 | 写法要点 |
|---|---|---|---|
| S–R 一阶线性近似 | Σ6/总=89.5%（面积）/91.3%（加权） | §7.1 | 影响方向（低估/高估）+ 已做的一致性 QC 数值 |
| 对齐损失 | 22 地点 391.7 人（0.047%） | §7.2 | 绝对量+占比，说明不改变结论的量级判断 |
| Σ8≠All | ≈4.5% | §7.3 | 独立子情景口径说明，指向 qc sheet |
```

自检：缺口表每一行都有落点行。Limitations 每一段都能指回缺口表或 sensitivity 证据。两边都不许有孤儿。

## 5. 审稿回复的数值纪律

- 回复中引用的每一个数，同样走对账表（审稿人会核）。
- 承诺的补充分析要走完整链（design → code → verify）。不要在回复里直接给未经验证的数。
- 修订稿与原稿的数字 diff 清单随回复落 diagnosis/。
