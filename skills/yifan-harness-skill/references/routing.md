# 路由细则与体检边界（yifan-harness-skill 深化材料）

按需加载。SKILL.md 是路由表速查。本文补充闸门对照、体检边界、宿主差异与降级行为。

## 闸门对照（多阶段连做的推进规则）

前一阶段放行，才进下一阶段。放行条件见下表。

| 闸门 | 从 → 到 | 放行条件（摘要） |
|---|---|---|
| G1 | 设计 → 代码 | 口径已拍板并登记；项目级含复现者检查；公式链/数据契约/维度速查成文 |
| G2 | 代码 → 验证 | HDD 分流判定成文；AT 先于 DEV 锁定且全过；QC 门通过 |
| G3 | 验证 → 可视化/写作 | Blocker 清零；QC 值可复算；审计报告落 diagnosis/ |
| G4 | 可视化 → 写作 | 双 QA（结构+视觉）过或如实标注；图件代次现行 |
| G5 | 写作 → 投稿 | 数值对账 100%；公式三处同步；术语统一 |

完整闸门表、回退路由与跨阶段协议见仓库的 `docs/workflow.md`（`<GROUP_ROOT>/docs/workflow.md`；`docs/` 不随入口分发，只在仓库里）。回退原则：退到根因所在层修，不在表象层打补丁。修复后重跑受影响的全部下游验证，并在当次 handoff 留痕。

## 任务分级：轻任务不启动全流程

先判级，再决定走多少流程。三个级别用平常话说，不用代号。

| 级别 | 判据 | 仪式 | 闸门 |
|---|---|---|---|
| 快算 | 单点数值、单图、单表；不新增或改动口径 | 声明预期值或预期性质，执行后核对；handoff 一行 | 不写设计文档，不启动设计访谈 |
| 小改 | 一个 step 内的改动、加一张敏感性图、换已拍板口径的呈现方式 | 聊天内确认口径点与预期；设计要点进 handoff | G1 简化 |
| 项目 | 新研究问题、新管线、新数据集、口径变更、要交付论文或报告 | 设计对话 + 设计文档 + 复现者检查 | G1 完整门禁 |

规则如下。

- 判级写进回复第一句。用户可覆盖级别。级别被覆盖时，记入 handoff。
- 中途变大就停下，回入口重判，按新级别重走仪式。禁止按快算开工、按项目交付。
- 多个独立研究问题，拆成子项目，逐一定义并排顺序。
- 拿不准级别时，按上一级处理。出现口径变更或正式交付物，就按项目级。
- 快算与小改也要留痕。载体是当次 handoff，不是设计文档。

分级细则见 research-design 的 `references/design-conversation.md`。分级通常不改变路由目标。项目级若 G1 未过，先路由 research-design 补设计，再进实现阶段。

## 体检边界情况

边界情形各有对应处置，不套默认路径。

| 情形 | 处置 |
|---|---|
| 体系在但 handoff 断档或失真 | 视同体系失真，走已有仓库路径的失真分支（考古先行） |
| 半途项目（做到某阶段中途接入） | 体检定阶段后直接续接，闸门从实际位置起算 |
| 工作区含多个项目 | 以当前工作目录所在项目为准；跨项目诉求路由 project-conventions |
| 非研究项目（纯软件/纯问答） | 说明本组不适用，不强行初始化；用户坚持则按 archetypes 判型（C 型存在） |
| 判型拿不准（A 至 E） | 路由 project-conventions 走需求确认协议（先听后问） |

判型速查：A 数据分析（默认）/ B 仿真·方法研究 / C 软件包 / D 手稿·综述 / E 应用·仪表盘。按交付物判。细则在 project-conventions 的 `references/archetypes.md`。

## 宿主差异

各宿主的入口路径与降级方式不同，技能本体不变。

- **支持范围**：本组支持 Qoder 与 DSH，统一经 `~/.agents/skills/yifan-harness-skill/` 这一个入口进入。
- **DSH（deepseek-harness）**：用户级技能根是 `~/.agents/skills`，项目级是项目根的 `.agents/skills`。无命名空间，经宿主技能工具调用。
- **技能缺失降级**：被路由技能在当前宿主不存在时，提示运行仓库根的 `scripts/install.ps1` 重新安装入口（它把 `<GROUP_ROOT>` 写成实际路径）。然后按 README 的约定降级执行：各阶段 SKILL.md 内联了最低约束，技能缺失时按内联规则走。

## 与子技能的触发分工

入口只收全流程意图，阶段意图由入口转交对应技能。

- 入口 description 只收全流程意图：启动/接管/初始化研究项目、不知道用哪个阶段技能、点名 yifan-harness-skill / 总入口（旧名 yifan-harness / asp 亦可）。阶段专属意图（画图、修 bug、对账、改稿）由入口按路由表直接落到对应阶段技能。
- 六个阶段技能已移出所有宿主扫描根，宿主看不见它们。因此不存在“入口与子技能并存”的第二条通道。子技能 frontmatter 里的触发词只在被入口读入后作为行为约束生效，不再自动触发。
- 已在某阶段技能的会话中时，无需回入口。阶段间推进与回退按 workflow 的闸门与回退路由执行。
- 入口被误触发到单一明确阶段（如用户只是说“画个图”）时，直接路由对应子技能，不启动全流程体检。
