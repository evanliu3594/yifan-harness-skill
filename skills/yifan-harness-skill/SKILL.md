# yifan-harness-skill：学术研究总入口

## Overview

本技能是六技能组（底座 project-conventions 加五阶段 research-design → code-implementation →
result-verification → data-visualization → manuscript-writing）的唯一入口。它只做两件事：确定目标
阶段，按路径把对应技能读进上下文。阶段流程由被读入的技能承担，本入口不重复阶段工作。

技能本体留在仓库里，不进宿主扫描根。入口只是分发副本：安装脚本把仓库的实际路径写入下面的第 1 条，
同一份 SKILL.md 因此可以装在任何机器上。旧名 yifan-harness、academic-superpowers（缩写 asp）
保留作兼容触发词，安装目录、脚本与命令一律用 yifan-harness-skill。

## 加载协议（每次路由先做这一步）

目标技能记为 `<name>`，按下面的真实路径读入：

1. 事实源：`<GROUP_ROOT>\skills\<name>\SKILL.md`
2. `<GROUP_ROOT>` 是仓库根（git 工作树所在目录），其下的 `skills/` 就是技能本体目录。技能本体只此一处。

读到字面的 `<GROUP_ROOT>` 时，说明入口未安装或安装不完整：先运行仓库根的 `scripts/install.ps1`，
或按 README 的「安装」节手工替换本文件里的该标记。路径不存在时停下，报告缺失路径的绝对形式，不凭记忆
复述子技能内容。

六个技能本体都在 `<GROUP_ROOT>\skills\` 下，互为兄弟目录，且不在任何宿主的扫描根里。宿主看不见它们，
它们 frontmatter 里的触发词因此不再自动生效，一律经本入口进入。读入某个技能后，该技能内部所有相对
路径都以它自己的目录为基准解析：它的 `references/`、`templates/` 落在 `<GROUP_ROOT>\skills\<name>\` 下，
因为技能互为兄弟目录。不要把这类路径改挂到本入口目录下。

扫描根里出现第二份含技能本体的目录，属双通道，删掉多余的一份。

## Iron Law

只调度，不执行。用 Read 按上面两条路径加载目标技能。不要用宿主的技能工具按名字调用，宿主目录里已经
没有这些名字。一次只推进一个阶段。不加载被读入技能的依赖。不改被读入技能的输出格式。体检期间不写任何
文件。先判任务级别（快算 / 小改 / 项目）。轻任务直通对应阶段，项目才启动完整设计闸门。任务变大回入口
重判。

## 路由表（有指令）

有指令时查表定阶段，再按加载协议读入对应技能。

| 用户指令（口语示例） | 路由到 | 闸门 |
|---|---|---|
| 设计实验 / 定口径 / 出方案 / 定公式链 | research-design | G1 |
| 写代码 / 实现 / 修 bug / 跑管线 | code-implementation | G2 |
| 验证 / 审计 / 核对数字 / QC | result-verification | G3 |
| 画图 / EDA / 可视化 / 改图 | data-visualization | G4 |
| 写论文 / 改稿 / 投稿 / 回审 | manuscript-writing | G5 |
| 初始化 / 接管 / 归档 / 删除 / 目录规范 / 留痕 | project-conventions | 全程 |
| 模糊描述或多阶段连做 | 先三问体检，再按闸门顺序路由 | 无 |

多阶段连做按 G1 至 G5 推进。闸门不放行，就停在当前阶段，并向用户说明原因。闸门对照见本技能目录下的
`references/routing.md`。

## 分级路由：轻任务不启动全流程

先判级，再决定走多少流程。快算直接进入对应阶段。小改在聊天内确认。项目先确认 G1 是否已过。G1 未过
时，先走 research-design 的完整设计对话，再进实现阶段。判级写进回复第一句。用户可覆盖级别。中途变大
就停下重判，不在旧级别上继续加做。判据见 `references/routing.md` 的“任务分级”节。分级细则另见
research-design 的 `references/design-conversation.md`。

## 无指令：三问体检（只读）

按顺序问，命中即停：

1. 体系完整？ 项目根有 `AGENTS.md` 路标与 `handoff/`，各目录有 `README.md`，需要时能指向规范文件 → 读最新一份交接（按文件名排序的最后一份）。
   定位当前阶段，按加载协议读入该阶段技能续接。向用户一句话汇报从哪里续接。
2. 有码无体系？ 有代码、数据或产物，但没有本框架的文档体系，或体系已失真 → 路由 project-conventions。
   走已有仓库路径：考古 → 对齐 → 建体系 → 补验证债。
3. 空仓库？ 空目录或只有原始数据 → 路由 project-conventions，走空仓库路径：判型 → 骨架 → 设计拍板。

体检动作限于列目录树，读 `AGENTS.md`、`handoff/` 与 README，看 git log。体检结论三行汇报：体系状态、
判型建议、下一步路由。结构性改动（建骨架、考古纳入）开工前，按 project-conventions 的需求确认协议先听
后问。体检与路由自动，口径与判型必问。

## Red Flags

以下想法会把工作带偏，出现就停。

- 想在本入口里写代码、画图、改稿 → 停，按加载协议读入对应阶段技能。
- 想用宿主技能工具按名字调 research-design 等 → 停，那些名字不在宿主技能目录内，只能按路径读。
- 体检发现既非研究项目也无数据 → 停，向用户说明本组不适用，不强行初始化。
- 用户指令与体检结论冲突 → 以用户指令为准，冲突点提醒用户记入当次 handoff。
- 想一次串完多个阶段 → 停，本入口一次一个。
- 没判级就开始列口径、写设计文档 → 停下。先判快算、小改或项目，仪式随级别走。
- 快算或小改被按项目级流程拖长 → 停下。回到当前级别。用户没有要求项目级仪式。

## Verification Checklist

交付前逐项核对，全部通过才收口。

- [ ] 已按路由表或三问体检确定唯一目标技能
- [ ] 已判任务级别（快算 / 小改 / 项目），并在回复第一句声明
- [ ] 用 Read 按路径加载，未用宿主技能工具按名调用
- [ ] 体检全程只读，未写任何文件
- [ ] 已声明以目标技能自身目录为基准解析其相对路径
- [ ] 目标缺失时给出缺失路径与 `scripts/install.ps1` 的安装命令，不编造流程
